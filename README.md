# 플래마켓 (fleamarket)

야외 플리마켓(프리마켓) 행사에서 판매자 부스 위치를 잡을 때 필요한 도면 배치 자동화 도구입니다.

## 시작하게 된 목적

행사장 도면(공원/광장 등)을 올리고, 어떤 기구(1500mm 테이블 몇 개, 1800mm 테이블 몇 개, 파라솔 몇 개 등)가
얼마나 들어가는지 입력하면 지정한 영역 안에 자동으로 배치해주는 걸 목표로 시작했습니다.

실제 운영을 생각하면 다음 조건들이 필요했습니다.

- 도면 파일이 DXF/DWG로 올 수도, PDF나 사진(이미지)으로만 있을 수도 있음 → 포맷에 상관없이 받아서 처리
- 화장실 접근로, 소방 동선, 나무처럼 기구를 놓으면 안 되는 구역이 있음 → 제외구역(데드존) 지정
- 배치 결과를 그대로 쓰기보다는 현장 사정에 맞게 손으로 미세조정해야 함 → 드래그/회전 가능
- 판매자마다 "전기를 많이 쓴다", "테이블 대신 행거가 들어온다", "아이스크림 기계가 들어온다" 같은 특이사항이 있지만,
  판매자 개인정보를 전부 관리하기엔 행사 특성상 부담스러움 → 자리별 가벼운 메모 + 개별 기구 교체로 대응

## 주요 기능

- DXF/DWG/PDF/이미지 도면 업로드 → 벽/영역 자동 인식 시도 (DXF는 실제 벡터 인식, 나머지는 best-effort)
- 자동 인식 결과를 캔버스에서 점을 드래그해 보정, 또는 직접 폴리곤을 그려 배치 영역 확정 (사각형이 아닌 임의의 다각형도 가능)
- 배치 영역 안에 제외구역(데드존)을 여러 개 지정 가능 — 외곽만 둘러 배치하는 도넛형 배치도 지원
- 기구 카탈로그를 프로젝트마다 자유롭게 추가 (이름/가로/세로/모양)
- 기구별 수량·최소 간격·회전 허용 여부를 입력하면 격자 기반으로 최대한 채워 자동배치
- 자동배치 결과를 개별 기구 단위로 드래그·회전으로 미세조정
- 특정 자리 하나만 수동으로 추가하거나, 기구 종류를 바꾸거나(예: 테이블 → 행거), 자유 메모(전기 사용량 등)를 남길 수 있음
- 사람이 손댄 자리는 자동배치를 재실행해도 지워지지 않고, 오히려 새 자동배치가 그 자리를 피해감
- PNG로 내보내기
- 프로젝트/도면/배치 결과는 서버(PostgreSQL)에 저장되어 여러 기기에서 이어서 작업 가능

## 기술 스택과 선택 이유

### 백엔드

| 기술 | 선택 이유 |
|---|---|
| **FastAPI** | Pydantic 기반이라 SQLModel과 자연스럽게 맞물리고, 타입 힌트만으로 요청/응답 검증과 API 문서(`/docs`)가 자동 생성돼 개발 속도가 빠름 |
| **SQLModel** | SQLAlchemy(ORM) + Pydantic(검증)을 한 클래스로 합쳐, DB 테이블 모델을 API 스키마로도 재사용 가능 |
| **PostgreSQL** | 여러 기기·사용자가 같은 프로젝트를 이어서 작업해야 해서 SQLite보다 동시접속에 적합한 걸 선택 |
| **ezdxf** | 순수 파이썬 DXF 읽기/쓰기 라이브러리. LWPOLYLINE/POLYLINE/ARC 등 엔티티를 세밀하게 다룰 수 있고 유지보수가 활발함 |
| **OpenCV (headless)** | PDF/이미지에서 윤곽선·직선 검출로 벽/영역을 추정하는 사실상 표준 라이브러리. headless 버전이라 서버에 불필요한 GUI 의존성이 없음 |
| **pdf2image + poppler** | PDF를 래스터 이미지로 바꾸는 표준 조합. poppler는 로컬 설치가 까다로워 Docker 이미지 안에 넣어 해결 |
| **shapely** | 제외구역(구멍 있는 다각형) 표현과 포함·겹침 판정을 표준 기하 라이브러리로 안전하게 처리 (`Polygon(shell, holes)`) |

### 프론트엔드

| 기술 | 선택 이유 |
|---|---|
| **React + TypeScript** | 상태가 많은 인터랙티브 에디터(도면+영역+기구+배치)에 컴포넌트 모델이 맞고, 백엔드 스키마와 어긋나는 실수를 컴파일 타임에 잡음 |
| **Vite** | dev 서버 기동/HMR이 빠르고 설정이 단순함, Docker 볼륨 마운트 환경에서도 잘 맞음 |
| **Konva / react-konva** | 캔버스 기반 2D 라이브러리로 다각형 꼭짓점 드래그, 기구 드래그·회전 같은 인터랙션을 SVG 직접 조작보다 훨씬 적은 코드로 구현 |
| **axios** | JSON API 클라이언트 코드를 간결하게 유지 |

### 인프라

| 기술 | 선택 이유 |
|---|---|
| **Docker / docker-compose** | opencv/poppler/psycopg2처럼 OS 의존적인 네이티브 라이브러리를 로컬에 개별 설치하지 않고 컨테이너로 통일된 개발 환경 제공 |

## 실행 방법

```bash
docker compose up -d
```

- 백엔드: http://localhost:8000 (API 문서: `/docs`)
- 프론트엔드: http://localhost:5173

## 알려진 제약사항

- DWG 파일은 오토데스크 독점 포맷이라 오픈소스로 직접 파싱할 수 없습니다. ODA File Converter를 설치하고
  `ODA_CONVERTER_PATH` 환경변수를 설정해야 처리되며, 미설정 시 DXF로 변환해서 다시 업로드해야 합니다.
- PDF/이미지의 영역 자동 인식은 OpenCV 기반 best-effort라 정확도가 낮을 수 있어 사용자 보정을 전제로 설계했습니다.
- PDF/이미지는 실제 축척 정보가 없어, 업로드 후 도면 단위당 실제 mm 값을 직접 입력해야 합니다.
- 자동배치 알고리즘은 격자 기반 greedy 방식으로, 완전 최적해를 구하는 빈패킹이 아닙니다. 0°/90° 축 정렬 배치만
  시도하기 때문에 삼각형·L자형처럼 각지고 좁은 영역에서는 실제 채울 수 있는 것보다 적게 배치될 수 있습니다.
